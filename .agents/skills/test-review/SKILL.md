# framework-sdk-go 测试审查

对每个测试给出「保留、改写、合并或删除」结论，并指出它保护的规范要求或公开不变量。

- 保留：能在缺陷复发时失败，覆盖公开 API、错误码与消息键、线上编码、取消与截止时间、并发、容量、生命周期次序或平台差异。
- 改写：只断言内部函数被调用、依赖未导出字段或 map 的遍历顺序、靠 `time.Sleep` 等固定延时、没有失败路径，或把期望值写成 Go 自己算出来的结果而不是向量或规范。
- 合并：与相邻用例输入和断言等价，不能提供额外定位。
- 删除：不可能失败、只验证常量或标准库本身，或已被更清晰的同层测试与向量回放完整覆盖。

## SDK 专项

- 向量回放读一致性模块内嵌的向量，逐项断言而不是只数通过的条数；回放的文件列在 `vectors_test.go` 的 `replayedVectors` 并注明测试名。
- 运行器测试必须核对用例序列等于运行器的全集，名单外的跳过算失败（运行器把跳过记为通过）。
- 插件运行时的时限与收尾用例看可观察结果（应答、状态、退出码），不靠长时间真实等待。
- 只在某个平台编译的测试（`//go:build windows` / `unix`）要有另一个平台上等价的覆盖，或说明为什么只属于这个平台。
- 存储与登记表的测试覆盖空状态、容量上限、过期、并发与批量的边界。

输出按风险排序并附文件和行号。除非用户要求运行，否则只做静态审查；不通过删除测试或放宽门禁解决生产缺陷。
